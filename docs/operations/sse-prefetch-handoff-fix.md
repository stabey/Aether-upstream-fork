# SSE 预读状态交接修复与影响审查

基线：a57df2e43（upstream/main d30268f80 + 全局模型名路由保护）。
范围：本地修复与测试，不包含镜像构建、推送或线上部署。

## “审计”为什么会影响转发

此处审计是请求/响应留档，用于管理台查询和故障排查，不是内容审核。
正常设计中，协议解析缓冲必须保持完整；预读检查可以限制检查范围；留档副本
则可以按内存预算截断。这三者的用途不同。

旧代码将 provider_prefetched_body 同时用于审计留档和后台解析器重建。
当首块已消费 17741 字节、副本只保存 16384 字节时，新解析器少恢复 1357 字节，
而上游读取游标已经前移，后续直接拼接剩余流，导致下游 JSON 损坏。
本次直接移动完整解析状态，诊断捕获不再决定转发或用量观察的输入。

## 引入经过

1. 531cf11025，2026-07-27，feat(gateway): harden provider request execution。
   该提交覆盖请求执行加固、Anthropic 兼容、有限预读和 OAuth 重试。
   对本问题的直接变化，是将完整的 provider_prefetched_body.extend_from_slice
   改为 append_stream_capture_bytes(..., MAX_STREAM_PREFETCH_BYTES)，最多保留 16 KiB。
   后续仍销毁预读解析器、重建解析器，再用该副本恢复状态。副本从完整数据变成
   诊断前缀，却继续承担协议状态恢复职责，是根本错误。

2. f2839ae6a7，2026-09-09，feat(routing): add strategy failover controls。
   一般 SSE 从收到响应头即提交，改为等待首个有意义事件（FirstSseSemanticEvent）。
   目的是识别 HTTP 200 内的错误，并在客户端收到内容前按路由策略切换候选。
   正常 Responses 流因此进入预读路径，暴露已有缺陷。关闭用户配置的故障切换
   不会撤销此通用 SSE 分支。

这些日期是代码提交日期，不代表 stabey-124 首次部署相关版本的时间。

旧设计重建解析器也避免了将借用请求上下文的对象移入 tokio::spawn 的生命周期问题；
这是从实现结构推断的动机，不是提交作者的明确说明。原始字节完整时重放可恢复状态，
但这种设计隐含“捕获副本永不截断”的条件，内存限制改动破坏了它。

## 证据与修复

两次实际故障都在 SSE 偏移 16384 处缺字节，缺口分别为 1357 / 1351 字节。
大 response.created 包含工具描述，事件尚未完整；首个 transport chunk 已被完整消费，
新解析器却只恢复前 16384 字节。之后继续读下一个 chunk，缺口拼入同一 JSON 行。

本次：
- AiSurfaceStreamRewriter、ProviderPrivateStreamNormalizer 增加 into_owned，移动
  当前缓冲、协议转换状态、事件类型和历史状态，只将借用的 report_context 转为自有数据。
- 网关移交这些对象，不重建、不重放，不复制已处理的流数据。
- 用量观察器及 provider error 检测器从预读开始消费完整的规范化数据，再原样移交。
- 上游审计从预读开始使用现有 StreamBodyCapture，受全局/每请求预算约束；一旦截断，
  保持连续前缀，不能把后续字节拼到缺口之后。字节计数使用真实消费量。
- 历史记录仍只提取/持久化一次。同步 JSON 转 SSE 的桥接路径仍停用原流解析器。
- 审计 JSON 在已有 dropped_chunks 之外记录 first_parse_error 的事件序号、行列和错误，
  不新增原始负载副本。它描述捕获数据解析失败，不能单独区分上游坏数据和审计截断。

选择保留解析状态，可以同时维持预读错误切换和内存预算。提高 16 KiB 阈值只会
把触发点推后；无限保存重放数据增加内存占用；跳过预读会丢掉首段错误切换能力。
这些替代方案都没有解决“诊断捕获兼任协议状态”的职责混用。

## 影响范围与取舍

| 方面 | 影响 |
|---|---|
| Responses 同格式 | 修复大首帧跨预读边界损坏；保留原兼容字段处理 |
| 跨协议转换、私有封装 | 同一交接路径受益，避免丢半帧、重置转换状态或事件 ID |
| Anthropic 直接透传 | 独立路径原本保留完整队列，没有本次状态重放修改；通用路径的停止/尾部排空语义保持 |
| 预读与故障切换 | 保留 16 KiB 检查预算、超时、路由规则及提交条件，没有提前提交 HTTP 200 |
| 同步 JSON 桥接 | 保持桥接结果、禁用原流观察器/转换器，避免重复输出 |
| 用量与错误检测 | 不再漏掉预读截断区间；部分旧版本误报成功或漏统计的请求可能产生不同、更准确的结果 |
| 内存 | 去掉重建/重放的重复处理；新增上下文所有权复制。审计可保留完整预读区间，可能比旧版本占用更多诊断内存，仍受现有全局及每请求预算约束 |
| CPU/首字延迟 | 避免重复解析；完整用量/错误观察提前到预读阶段，可能增加该阶段工作量。未进行压力/延迟基准测试，不能承诺无性能代价 |
| 存储/API | 审计 metadata 新增可选 first_parse_error；无数据库迁移，响应协议和 API 参数不变 |
| 极大或本来就损坏的事件 | 保留既有解析缓冲上限及容错行为；不声称修复所有上游坏 JSON、网络断流或所有 SSE 边界问题 |

因此不能称为“全部正影响且零风险”。主要收益是数据完整性和正确观察状态；
主要验证风险在跨协议状态延续、一次性历史/用量语义、同步桥接与预读内存行为。

## 验证设计

- 网关首帧交接：16383 / 16384 / 17735 / 17741 字节，以及多个预读块累计越界。
- 完整大事件已在预读输出，以及私有封装半帧跨交接；校验终结事件只输出一次、
  上游审计事件完整和精确用量。
- 底层 ownership 交接：UTF-8 字符中间分块、Responses→Chat 转换、Windsurf 二进制帧。
- 审计预算为零：转换与用量观察不依赖日志捕获，交接仍完整。
- 原有 stream 目录测试覆盖首段错误切换、晚期错误、Anthropic 停止/尾部、
  超时取消、控制帧、同步桥接与终结状态。
- 审计部分 JSON 失败后接正常终结：元数据明确记录错误，不把剩余合法事件当作全流完整。
